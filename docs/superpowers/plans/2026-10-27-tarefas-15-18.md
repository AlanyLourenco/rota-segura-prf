# Tarefas 15–18 (fechamento da PoC) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fechar as tarefas pendentes de `tasks.md` (15–18) e a lacuna de rastreabilidade numérica em parágrafos com notícia.

**Architecture:** Mudanças pequenas e locais nos módulos existentes (`privacy.py`, `news.py`, `guardrails.py`) + um módulo novo `evals.py` com conjunto golden em JSON. Nenhuma mudança no fluxo do grafo além de passar dados extras ao `output_guard` e trocar a fonte das notícias quando há snapshot.

**Tech Stack:** Python 3.10, pydantic, DuckDB, LangGraph, pytest, ruff.

**Spec:** `.kiro/specs/relatorio-seguranca-viaria/{requirements,design,tasks}.md` (R6, R7, R8.2).

## Global Constraints

- LLM nunca calcula números; métricas só em `metrics.py`.
- Nada por pessoa ao LLM; tudo passa por `data/privacy.py` (`assert_llm_safe`).
- Todo nó/tool do grafo registra evento via `audit.AuditLogger`.
- `min_cell_size = 5` (config); célula primária suprimida exibe `"<5"`.
- Comandos de verificação: `.venv/Scripts/python -m pytest -q` e `.venv/Scripts/ruff check src tests`.
- SDD: atualizar spec (`requirements.md`/`design.md`) **antes** do código; marcar `[x]` em `tasks.md` ao concluir.
- Texto/identificadores no idioma do código existente (pt-BR em docstrings e mensagens).
- Branch de trabalho: `feat/tarefas-15-18` (criar a partir de `main`).

## Review Focus

1. Parágrafo `BASE + NEWS:1` com número inventado → hoje passa; deve reprovar (`numero_nao_rastreavel`). Teste na Task 3.
2. Parágrafo só `NEWS:1` com número que não está no título/snippet da notícia → deve reprovar. Teste na Task 3.
3. Grupo (`estado_fisico`) com exatamente uma célula `<5` → o valor seria deduzível pelo total (`deaths`); deve haver supressão complementar. Teste na Task 1.
4. `--news-from` apontando para arquivo inexistente ou JSON inválido → erro claro, exit 1, manifesto `status=error`. Teste na Task 2.
5. Caso golden com regra esperada digitada errado (ex.: `"pi"`) → o loader deve falhar, não passar em silêncio. Teste na Task 4.

### Task 4: Conjunto golden de avaliação dos guardrails (T15, R6)

**Files:**
- Create: `evals/golden_guardrails.json`, `src/rota_segura/evals.py`, `tests/test_golden.py`
- Modify: `src/rota_segura/cli.py` (subcomando `eval`), `.kiro/steering/structure.md` (pasta `evals/`), README (seção Avaliação)

**Interfaces:**
- Consumes: `validate_draft(..., news_numbers=...)` (Task 3), `validate_request` + `InputRejected`.
- Produces (em `evals.py`):
  - `class GoldenCase(BaseModel)`: `id: str`, `kind: Literal["input", "output"]`, `category: str`, `uf: str | None = None`, `focus: str | None = None`, `draft: Draft | None = None`, `allowed_numbers: list[float] = []`, `news: dict[int, str] = {}` (id → texto título+snippet), `expect_pass: bool`, `expect_rules: list[str] = []`. Validador: `expect_rules ⊆ KNOWN_RULES`, `kind=="output"` exige `draft`.
  - `KNOWN_RULES = frozenset({"pii", "numero_nao_rastreavel", "sem_fonte", "fonte_invalida", "causa_de_noticia"})`.
  - `run_case(case) -> CaseResult` (`id`, `category`, `ok: bool`, `got_rules: list[str]`); ok = (passou == `expect_pass`) e `set(expect_rules) ⊆ set(got_rules)`. Para `input`: passou = não lançou `InputRejected`.
  - `run_suite(path: Path = DEFAULT_CASES) -> SuiteResult` (`total`, `ok`, `results`, `by_category: dict[str, tuple[int, int]]`).
- CLI: `rota-segura eval [--cases PATH]` imprime uma linha por categoria (`categoria ok/total`) + falhas; exit 0 se tudo ok, senão 1.

Conteúdo mínimo (≥ 24 casos): input — injeção (4: "ignore as instruções", "system prompt", inglês, em meio a texto válido), fora de escopo (3), UF inválida (2), válidos (3); output — PII (3: CPF, placa Mercosul, e-mail), número inventado em BASE (2), em parágrafo misto (2, Review Focus 1–2), sem fonte (1), fonte inexistente (1), causa a partir de notícia (2), hipótese com notícia permitida (1), limpos com arredondamento pt-BR (2). Dados sintéticos, nenhum dado real de pessoa.

  - `test_golden_has_minimum_coverage`: `total >= 24` e categorias incluem `{"injecao", "pii", "numero", "causa", "limpo"}`.
  - `test_unknown_expected_rule_rejected`: `GoldenCase(..., expect_rules=["pi"])` → `pytest.raises(ValidationError)`.
